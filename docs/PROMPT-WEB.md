# برومبت بناء نسخة ويب بـ HTML / CSS / JS

> ملف مواصفات جاهز للنسخ واللصق في أي مساعد برمجي، لتوليد **نفس تطبيق أجواء**
> بنفس المزايا والمكوّنات والتفاصيل — لكن بتقنيات الويب النقي (بلا frameworks
> وبلا build step وبلا مفاتيح API).

**كيف تستخدمه**

1. انسخ محتوى الكتلة أدناه كما هو.
2. أرسله كرسالة واحدة إلى المساعد.
3. لو قصّر في بعض الملفات، اكتب: «كمّل من حيث توقفت، الملف رقم كذا».

**تعديلات سريعة**

| الحاجة | ما تغيّره |
|---|---|
| نسخة أصغر بلا توثيق | احذف القسم `14) المخرجات المطلوبة` |
| استخدام React / Vue | استبدل القسم `2) قيود تقنية صارمة` بالكامل |
| بدون مصدر GDACS البديل | احذف البند `6` من قائمة المصادر |
| بدون GPS | احذف البند `4` وشيت الترحيب، واجعل القاهرة هي البداية دائمًا |

ألوان الخطورة:

  warning → amber  (#E0A33E)
  severe  → red    (#D9534F)

الثيمات: نظام / فاتح / داكن (system | light | dark)

  • فاتح: خلفية بيضاء مزرقة (#F3F7FB) بنفس الهالات ولكن بشفافية أقل.
  • الكروت: سطح زجاجي (rgba + backdrop-filter: blur)، حدود 1px شفافة،
    زوايا 20–24px، ظل ناعم جدًا.

المسافات: 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 px
أنصاف الأقطار: 10 / 14 / 18 / 24 / 999 (pill)
العرض الأقصى للمحتوى: 860px، ويُوسَّط أفقيًا مع padding جانبي 20px.
الشبكات: 3 أعمدة للتفاصيل على ≥720px، 2 على ≥520px، 1 على الجوال.

الأرقام دائمًا لاتينية (Western digits) في اللغتين، بينما أسماء الشهور

5) مصادر البيانات (كلها مجانية وبلا مفاتيح)
════════════════════════════════════════
1) التوقعات:
   GET https://api.open-meteo.com/v1/forecast
     ?latitude={lat}&longitude={lon}&timezone=auto
     &current=temperature_2m,relative_humidity_2m,apparent_temperature,is_day,
       precipitation,rain,showers,snowfall,weather_code,cloud_cover,
       pressure_msl,wind_speed_10m,wind_direction_10m,wind_gusts_10m
     &hourly=temperature_2m,precipitation_probability,precipitation,
       weather_code,wind_speed_10m,visibility
     &daily=weather_code,temperature_2m_max,temperature_2m_min,sunrise,sunset,
       uv_index_max,precipitation_sum,precipitation_probability_max,
       wind_speed_10m_max

2) جودة الهواء والغبار:
   GET https://air-quality-api.open-meteo.com/v1/air-quality
     ?latitude={lat}&longitude={lon}&timezone=auto
     &current=dust,pm10,pm2_5,us_aqi,european_aqi,uv_index
     &hourly=dust,pm10

3) البحث عن المدن:
   GET https://geocoding-api.open-meteo.com/v1/search
     ?name={query}&count=10&language={ar|en}&format=json

4) عكس الإحداثيات إلى مدينة:
   GET https://api.bigdatacloud.net/data/reverse-geocode-client
     ?latitude={lat}&longitude={lon}&localityLanguage={ar|en}

5) الأعاصير (المصدر الأساسي):
   GET https://eonet.gsfc.nasa.gov/api/v3/events
     ?category=severeStorms&status=open&days=60

6) الأعاصير (مصدر بديل):
   GET https://www.gdacs.org/gdacsapi/api/events/geteventlist/SEARCH

قواعد التعامل مع الشبكة:
  • timeout = 18 ثانية، و3 محاولات فقط للأخطاء العابرة
    (network / timeout / 5xx / 429) مع تأخير متزايد 350ms × رقم المحاولة.
  • الاستجابات المشوّهة (JSON غير صالح) لا تُعاد المحاولة إطلاقًا.
  • مصادر (2) و(5)/(6) اختيارية: فشلها يُخفي قسمها فقط ولا يكسر الصفحة.
  • GDACS قد لا يرسل CORS: جرّبه بعد EONET، وإن فشل أظهر حالة
    «بيانات الأعاصير غير متاحة حاليًا» بهدوء. لا تخفِ القسم بالكامل.

════════════════════════════════════════
6) قواعد المجال (Domain Rules) — طبّقها حرفيًا
════════════════════════════════════════
الوحدات:
  التخزين والحساب داخليًا بالمترية دائمًا، والتحويل للعرض فقط.
  حرارة: °C → °F = c×9/5+32
  رياح/مسافة: km/h → mph = ×0.621371
  هطول: mm → in = ×0.0393701

تصنيف الغبار (µg/m³):
  < 20 منخفض | < 50 متوسط | < 100 مرتفع | ≥ 100 مرتفع جدًا

مؤشر UV:
  < 3 منخفض | < 6 متوسط | < 8 مرتفع | < 11 مرتفع جدًا | ≥ 11 خطير

جودة الهواء (US AQI):
  ≤ 50 جيد | ≤ 100 مقبول | ≤ 150 ضار للفئات الحساسة
  | ≤ 200 غير صحي | ≤ 300 غير صحي جدًا | > 300 خطير

قيم مشتقة:
  • نقطة الندى: معادلة Magnus من الحرارة والرطوبة.
  • المدى البصري: أقرب قيمة visibility من بيانات الساعة الحالية.
  • UV الحالي: من جودة الهواء، وإن غاب استخدم uv_index_max اليومي.
  • مسافة الإعصار: haversine. تحويل العقدة إلى km/h = ×1.852.

محرّك التنبيهات (رتّبها بالخطورة ثم بالنوع):
  حرارة   : تبدو كأنها ≥ 38°C  → تحذير،  ≥ 43°C → خطير
  برودة   : تبدو كأنها ≤ 0°C    → تحذير،  ≤ -10°C → خطير
  رياح    : max(gust, speed) ≥ 40 km/h → تحذير، ≥ 70 → خطير
  مطر     : الحالي ≥ 2.5mm أو الست ساعات القادمة ≥ 10mm → تحذير
            الحالي ≥ 8mm أو الست ساعات ≥ 25mm → خطير
  غبار    : dust ≥ 50 أو PM10 ≥ 150 → تحذير
            dust ≥ 150 أو PM10 ≥ 300 → خطير
  أشعة    : UV ≥ 8 → تحذير، UV ≥ 11 → خطير
  رعد     : WMO ≥ 95 → تحذير، ≥ 96 → خطير
  إعصار   : أقرب إعصار ≤ 1000km → تحذير، ≤ 500km → خطير

مستوى خطورة الإعصار حسب سرعة الرياح:
  ≥ 118 km/h = خطير (أحمر) | ≥ 63 = تحذير (برتقالي) | أقل = معلومة (تركواز)

خرائط WMO → الحالة:
  0 صافي | 1-2 صافي غالبًا | 3 غائم | 45-48 ضباب | 51-57 رذاذ
  | 61-65 مطر | 66-67 مطر متجمد | 71-77 ثلج | 80-82 زخات
  | 85-86 زخات ثلج | 95 عاصفة رعدية | 96-99 رعد مع برد

7) التخزين والكاش
════════════════════════════════════════
استخدم localStorage بالمفاتيح التالية حرفيًا:
  ajwaa.settings.v1        → { localeCode, unitSystem, themeMode, hasSeenWelcome }
  ajwaa.cities.v1          → { cities: [...], selectedId }
  ajwaa.selectedCity.v1    → id
  ajwaa.onboardingSeen.v1  → boolean
  ajwaa.weather.v1.{cityId} → { fetchedAt, latitude, longitude, forecast, air, storms }

السلوك:
  • خزّن الاستجابات الخام (raw JSON) لا الكائنات المعالجة، وأعد تحليلها دائمًا
    بنفس الـparser.
  • صلاحية الكاش: 10 دقائق. إن تحرّك المستخدم أكثر من 5 كم عن إحداثيات
    الكاش، اعتبره غير صالح.
  • عند فشل الشبكة ومع وجود كاش متوافق: اعرض الكاش مع شريط واضح
    «بيانات محفوظة — قد لا تكون محدّثة».
  • احتفظ بآخر 8 مدن فقط في الكاش وامسح الأقدم.
  • أي بيانات تالفة في localStorage يجب ألا تكسر التطبيق: ارجع للافتراضيات
    (اللغة من المتصفح، الوحدات مترية، الثيم system، القاهرة كمدينة أولى).
  • الكتابة best-effort داخل try/catch.

════════════════════════════════════════
8) المكوّنات — واحد واحد، بنفس الترتيب
════════════════════════════════════════
(أ) شاشة التحميل الأولى (Bootstrap Loader)
    شعار SVG متحرك (طفو خفيف) + «أجواء · Ajwaa» بتدرّج ذهبي→تركوازي
    + الشعار النصي. تختفي بتلاشي 400ms عند أول رسم.

(ب) الهيدر (Sticky)
    يمين/يسار حسب الاتجاه: اللوجو + «Ajwaa» + الشعار النصي.
    وعلى الطرف المقابل 4 عناصر: مبدّل AR|EN (شريحة pill)، زر بحث،
    زر إعدادات. أزرار دائرية 40px مع tooltip وaria-label.

(ج) كارت البطل (Hero Card)
    • شريحة المدينة (قابلة للنقر لفتح منتقي المدن) + شارة «مباشر» بنقطة نابضة.
    • الحرارة الحالية بخط ضخم (72px+) مع وحدة صغيرة.
    • وصف الحالة + «تبدو كأنها X°» + «العظمى X° · الصغرى X°».
    • فاصل، ثم: «الوقت المحلي» + شارة المنطقة الزمنية (GMT+3)
      + ساعة حيّة تتحدث كل ثانية (HH:MM:SS) + اليوم والتاريخ.
    • زر تحديث دائري + «محدّث منذ X دقيقة».
    • خلفية الكارت = مشهد طقس متحرك حسب الحالة والليل/النهار:
      سحاب ينجرف، مطر، نجوم، هلال/شمس بهالة متوهجة. (SVG/CSS فقط)

(د) شريط عدم الاتصال (Offline Banner) — يظهر فقط عند العرض من الكاش.

(هـ) التنبيهات (Alerts)
    عنوان + عدد التنبيهات. كل تنبيه كارت ملوّن حسب الخطورة مع أيقونة،
    عنوان قصير، شرح عملي (مثال: «أغلق النوافذ واستخدم كمامة إن اضطررت
    للخروج»)، وشارة الخطورة. النقر يفتح صفحة شرح.

(و) الساعات الـ24 القادمة
    شريط أفقي قابل للتمرير: «الآن» ثم كل ساعة:
    الوقت + أيقونة الحالة + الحرارة + احتمال المطر + الرياح.
    الساعة الحالية مُبرزة بخلفية primary شفافة.

(ز) المطر والغبار (كارتآن متجاوران)
    كارت الغبار: القيمة µg/m³، تصنيف الغبار، شرح صحي،
      رسم بياني مساحي لـ24 ساعة، وثلاث شارات: مؤشر الغبار / PM2.5 / PM10.
    كارت المطر: إجمالي mm، «أمطار خلال 24 ساعة»، احتمال المطر الآن،
      وشريط منقّط لساعات المطر القادمة.
    في الكارت الضيق تظهر ملاحظة «اسحب أفقيًا لاستعراض الساعات القادمة».

(ح) تفاصيل الطقس (شبكة)
    الرطوبة (+ نقطة الندى) | الرياح (+ الاتجاه والهبّات) | احتمال المطر
    | مؤشر UV (+ التصنيف) | الضغط (hPa) | المدى البصري (km) | الغطاء السحابي (%)
    كل بطاقة: أيقونة ملوّنة + تسمية + قيمة كبيرة + سطر تفسيري.
    النقر على أي بطاقة يفتح Sheet يشرح معنى الرقم.

(ط) مسار الشمس
    قوس SVG من الشروق إلى الغروب، مؤشر متوهج لموقع الشمس الآن،
    وأسفل القوس: الشروق (HH:MM) والغروب (HH:MM) والوقت الحالي.

(ي) الأعاصير النشطة
    عنوان + سطر «أقرب الأنظمة المدارية». كل صف: أيقونة إعصار، الاسم،
    المسافة (X كم)، سرعة الرياح (كم/س)، شارة الخطورة، سهم يفتح المصدر.
    حالات: قائمة / لا توجد أعاصير / المصدر غير متاح.

(ك) توقعات 7 أيام
    صف لكل يوم: اسم اليوم (اليوم/غدًا/اسم اليوم) + أيقونة + احتمال المطر
    + شريط مدى حراري مُوحّد على مستوى الأسبوع (تدرّج أزرق→ذهبي→برتقالي)
    + العظمى/الصغرى. النقر يفتح تفاصيل اليوم (مطر، رياح، UV، شروق، غروب).

(ل) الفوتر
    اللوجو + «Ajwaa» + سطر الإسناد + روابط المزوّدين
    (Open-Meteo · NASA EONET · GDACS · BigDataCloud)
    + «صُنع بواسطة Mohamed Ibrahim · الإصدار 1.0.0»
    + «بيانات مفتوحة مجانية. لا تحتاج مفاتيح API.»

(م) هيكل التحميل (Skeleton)
    نسخة رمادية متلألئة (shimmer) من نفس تخطيط الصفحة، بلا قفزة في التخطيط.

(ن) شاشة الخطأ
    رسالة مُعرّبة حسب نوع الخطأ (شبكة/مهلة/سيرفر/بيانات غير صالحة)
    + زر «إعادة المحاولة».

(س) الـSheets (Bottom Sheets على الجوال، Modal على الديسكتوب)
    1. منتقي المدن: حقل بحث (debounce 380ms)، «موقعي الحالي»، المدن
       المحفوظة (قابلة للحذف بالسحب)، المدن الشائعة كشرائح، نتائج البحث.
    2. الإعدادات: المظهر (نظام/فاتح/داكن) — الوحدات (متري/إمبراطوري) —
       اللغة (العربية/English) — الخصوصية — مصادر البيانات — حول —
       التراخيص — ملاحظة البيانات.
    3. الترحيب (مرة واحدة): «أين أنت؟» + زر «السماح بالموقع» +
       «اختيار مدينة» + «ليس الآن». يُحفظ القرار ولا يظهر مرة أخرى.
    4. شيتات الشرح: لكل رقم/تنبيه/يوم، مع صفوف تفاصيل وأيقونات.

(ع) إشعارات Toast / Snackbar
    «أُضيفت {المدينة} إلى مدنك»، ورسائل الأخطاء القصيرة.

9) التفاعلات والحركة (بدون أي مكتبة)
════════════════════════════════════════
• دخول متدرّج للأقسام عند التحميل (fade + translateY، تأخير 60ms بين الأقسام).
• كل عنصر قابل للنقر: scale(0.97) عند الضغط + ظل متغيّر.
• الساعة الحيّة: تحديث كل ثانية بـ requestAnimationFrame أو setInterval.
• مشهد الطقس: سحاب يتحرك أفقيًا ببطء، مطر متساقط، نجوم تومض، هالة شمس نابضة.
• Skeleton بشيمر متحرك (linear-gradient + background-position).
• تبديل المدينة: انتقال تلاشي/انزلاق للكارت البطل.
• فتح/إغلاق الـsheets: انزلاق من الأسفل + خلفية معتمة + drag-to-dismiss.
• سحب للأسفل للتحديث (Pull to refresh) على اللمس.
• احترم prefers-reduced-motion: أوقف كل الحركات التكرارية.

════════════════════════════════════════
10) التعريب و RTL
════════════════════════════════════════
• ملف i18n بقاموسين ar و en، وكل نص في الصفحة يُطبَّق عبر [data-i18n].
• عند اختيار العربية: <html lang="ar" dir="rtl">، وعند الإنجليزية: lang="en" dir="ltr".
• استخدم الخصائص المنطقية فقط: margin-inline, padding-inline, inset-inline,
  text-align: start/end — ممنوع left/right في التخطيط.
• اقلب الأيقونات الاتجاهية (الأسهم/الشيفرون) تلقائيًا مع الاتجاه.
• أسماء الشهور وأيام الأسبوع عبر Intl.DateTimeFormat باللغة الحالية.
• الاحتفاظ بالأرقام لاتينية في اللغتين.
• التبديل فوري دون إعادة تحميل الصفحة، ويُحفظ في localStorage.

11) الوصولية (Accessibility)
════════════════════════════════════════
• كل زر وكل عنصر تفاعلي: عنصر دلالي صحيح (button/a) أو role + tabindex.
• aria-label / aria-live ملائمة (خاصة الساعة والتحديثات والتنبيهات).

• تباين ألوان AA على الأقل في الثيمين.
• alt/aria-hidden صحيحة لكل SVG زخرفي.

## ملاحظات على الدقة

**1. GDACS و CORS**
في نسخة Flutter كان GDACS مصدرًا بديلًا للأعاصير. في الويب النقي قد يرفض
المتصفح قراءة الاستجابة لأن الخادم لا يرسل `Access-Control-Allow-Origin`.
عالجناه في البرومبت بجعل **NASA EONET** هو المصدر الأساسي (يدعم CORS)،
مع تراجع هادئ إلى GDACS إن أمكن — بدل اكتشاف المشكلة بعد اكتمال الكود.

**2. شعار SVG داخل الكود**
البرومبت يطلب إعادة رسم الشعار بـ SVG بدل الاعتماد على صورة PNG، لأن ذلك
يضمن نفس الحدّة على كل المقاسات، ويمنع اختلاف الشكل بين الأيقونة والهيدر
وشاشة التحميل.

**3. الأرقام والعربية**
الأرقام تبقى لاتينية في اللغتين (كما في التطبيق الأصلي)، بينما الشهور
وأيام الأسبوع تُترجم عبر `Intl.DateTimeFormat`. لا تستخدم
`Intl.NumberFormat('ar-EG')` لأنه ينتج أرقامًا هندية.
